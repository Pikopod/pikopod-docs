```text
pikopod [command] [flags]
```

Every command accepts `--config <path>`, which defaults to `./pikopod.yaml`. `pikopod --version` prints the version, commit and date. `pikopod --help` lists the commands in the six sections below; nothing is hidden, and every section is one `--help` away.

## Exit codes

`0` clean, `1` the check ran and failed, `2` pikopod or configuration error. See [Exit codes](/operations/exit-codes).

## Errors

Every error is one line on stderr: what failed, why, the next action, and a docs link.

```text
error: no configuration found: pikopod.yaml does not exist → run `pikopod init` to scaffold one, or pass --config → https://github.com/pikopod/pikopod/blob/main/docs/config-reference.md
```

## Sandbox

| Command | What it does |
|---|---|
| [`import`](/reference/cli/import) | Import a spec or a docs URL into a sandbox. |
| [`up`](/reference/cli/up) | Serve the sandbox on `:4600` and the agent on `:4700`. |
| [`mode set`, `show`, `clear`, `verify`](/reference/cli/mode) | Put a running sandbox into a scenario's standing state, and check what your tests sent against it. |
| [`chaos`](/reference/cli/chaos) | Arm a fault on a running sandbox. |
| [`rule list`, `add`, `drop`, `check`](/reference/cli/rule) | Answer a declared operation by rule when the request or stored state looks a certain way. |
| [`webhook emit`, `list`](/reference/cli/webhook) | Fire a declared event; inspect deliveries. |
| [`requests`](/reference/cli/requests) | What a running sandbox received; `--explain` replays one request with decision tracing. |
| [`reproduce`](/reference/cli/reproduce) | Turn a recorded production failure into a scenario and run it. |

## Old spellings

This release still accepts the previous spellings, each printing one line on stderr naming the new one: the twelve observe commands at the top level (`pikopod incidents`, `pikopod status`, and so on), `pikopod sandbox requests`, `pikopod why`, `pikopod scenario reproduce`, and `pikopod scenario run`. The new command's `--help` names its old spelling.

## What needs what

| Needs | Commands |
|---|---|
| `pikopod up` running | `agent status`, `agent accept`, `chaos`, `mode`, `webhook`, `requests`, and the MCP control tools. `agent ack` works offline too. |
| A model key | `scenario create`, `fix`, and `import` from a docs URL that has no spec any other way. |
| A git repository | `pr open`, `pr comment`, `fix --pr`, and `spec-diff` with a `git:` source. |
| No config file at all | `demo`, `spec-diff`, `pr comment`, `pr open`. |
